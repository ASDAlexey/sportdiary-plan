# Ранбук

Операционные инструкции. SOP для агента лежат в `AGENTS.md`; здесь — настройка и редкие задачи.

## Подключение Coros MCP

1. Настройка живёт только в мобильном приложении Coros (профиль → настройки → COROS MCP),
   но вводить там ничего не нужно: URL `https://mcp.coros.com/mcp` (Option 1 на экране)
   уже прописан в `.mcp.json`.
2. В Claude Code при следующем запуске в этом репозитории — одобрить проектный MCP-сервер
   из `.mcp.json` (статус видно командой `/mcp`).
3. В Codex добавить в `config.toml` (streamable HTTP; свериться с актуальной докой Codex):

   ```toml
   [mcp_servers.coros]
   url = "https://mcp.coros.com/mcp"
   ```

4. Authorization Management в приложении: refresh отзывает всех авторизованных клиентов
   разом. Если MCP перестал подключаться — обновить авторизацию там и переподключиться.
5. Проверка: попросить агента перечислить недавние активности. Если в харнессе нет поддержки
   MCP — использовать файловые дропы `raw/` (см. AGENTS.md).

Coros анонсировал «Write training plans» (Coming soon) — синхронизацию планов на часы.
Когда заработает: рассмотреть заливку `data/plan/` на watch через MCP.

## Первый запуск после клона

```bash
cd tools/runkit && cargo build --release
cd site && pnpm install
```

## Ежедневный и недельный ритм

- После пробежки: сказать агенту «я побегал» (SOP в AGENTS.md). Он запишет тренировку,
  перегенерирует отчеты, ответит обратной связью.
- Воскресенье (или по запросу): агент готовит план следующей недели.
- Отчеты: `cd tools/runkit && cargo run --release -- report`. Руками `reports/` не править.

## Публикация

- GitHub: создать **публичный** репозиторий, запушить, включить Pages (Source: GitHub Actions).
  Workflow в `.github/workflows/site.yml` собирает и публикует `site/` на каждый пуш в `main`.
  Бесплатно.
- GitLab: зеркалировать репозиторий; `.gitlab-ci.yml` публикует `site/` через GitLab Pages.
  Бесплатно.
- Переименование репозитория: локально чинить нечего — CI сам передает имя репозитория как
  `NEXT_PUBLIC_BASE_PATH`.

## Бэкфилл истории

При первом подключении Coros MCP: выгрузить всю доступную историю активностей (не только
последние 90 дней — чем больше данных, тем лучше), записать в `data/workouts/`
(`source: coros-mcp`), найти тестовую тренировку середины сентября 2026 (пометка fitness-test)
и точную запись забега 2026-09-27, заполнить базовый недельный объём в
`data/athlete/alexey.yaml`, затем `runkit validate`, `runkit report` и пересборку сайта.
GPS-треки в YAML не писать. Текущий статус и подробный план — `docs/onboarding-status.md`.

## Локальные данные, которые не публикуются

- `raw/` — выгрузки с часов/Strava (содержат GPS-треки).
- `data/health/` — сон/HRV.

Оба пути в gitignore; перед коммитом в сомнительных случаях проверять `git status`.
